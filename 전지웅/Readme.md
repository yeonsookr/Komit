# 개인 학습 기록 — 전지웅

> 담당: FE / AI · 기록 기간: 2026.08.24 ~

### 📅 2026-08-27 (목)

**오늘 한 것**
- 특화PJT 1차 전문가 리뷰에 참여해 프로젝트의 AI 활용 방향과 금융 서비스 아키텍처에 대한 피드백 정리
- 웹은 계약과 분석 결과를 관리하고 앱은 사용자 코드베이스를 조회해 서버로 전달하는 역할로 분리 검토
- 웹 AI와 앱 AI의 담당 기능을 구분한 Git 브랜치 전략 및 협업 가이드 확인

**배운 것 / 정리**
- 향후 AI 고도화를 위해서는 상담 원문만 저장하는 것보다 AI 생성 결과와 실제 수행 결과를 분리하고, 요청부터 결과까지 연결되는 데이터를 축적하는 것이 중요하다.
- 금융 기능은 일반 서비스 장애와 달리 자금 정합성에 직접 영향을 주므로 서버 분리뿐 아니라 중복 지급 방지, API 타임아웃, 동시 요청과 장애 복구까지 함께 설계해야 한다.
- 웹과 앱은 서로 다른 모델을 쓰는 기준보다 입력 수집과 사용자 기능의 책임을 나누고, 공통 AI 처리는 서버에서 관리하는 방향이 적절하다.

**막힌 것 & 해결**
| 문제 | 원인 | 해결 |
|---|---|---|
| KISA 취약점 분석 가이드를 AI 코드 분석에 적용하는 방식이 구체화되지 않음 | 룰 기반 검사와 LLM 분석의 역할 및 검증 기준이 정해지지 않음 | Semgrep으로 KISA 기준의 정적 분석 룰을 적용하고 Gitleaks로 API 키·비밀번호 등 비밀정보 노출을 탐지한 뒤, LLM은 탐지 결과 설명과 수정 가이드 생성에 활용하는 방향으로 역할을 분리함 |

### 📅 2026-08-26 (수)

**오늘 한 것**
- 바이브코더 대상 프로젝트 설문조사 질문을 검토하고 문항의 표현과 흐름을 정리
- 익일 전문가 세션에서 확인할 질문과 프로젝트 기획 내용을 팀원들과 재검토
- 개인 학습 기록 문서와 팀 진행 기록을 정리하고, 문서 작업 브랜치를 `develop`에 병합
- 팀 Git 브랜치 전략(`main` ← `develop` ← 작업 브랜치)에 맞춰 커밋 진행

**배운 것 / 정리**
- 전문가 세션 전에는 기능 설명보다 현재 가설, 확인이 필요한 부분, 의사결정 기준을 질문으로 정리하는 것이 중요하다.
- 보호 브랜치에는 직접 작업하지 않고 작업 브랜치에서 문서와 코드를 관리하면 변경 이력과 리뷰 흐름을 명확하게 유지할 수 있다.

**막힌 것 & 해결**
| 문제 | 원인 | 해결 |
|---|---|---|
| 설문과 전문가 질문의 범위가 넓어질 수 있었음 | 확인하려는 가설과 질문의 목적이 섞여 있었음 | 질문별로 확인 대상과 의사결정에 활용할 내용을 기준으로 다시 검토함 |

### 📅 2026-08-24 (월)

**오늘 한 것**
- 특화PJT 1차 전문가 리뷰에 제출할 프로젝트 소개와 AI·금융 아키텍처 관련 사전질문 검토
- 와이어프레임 전체 화면을 검토하고 인증, 개발자 탐색, 프로필, 정산, 리뷰 및 신고 흐름의 수정사항 확인

**배운 것 / 정리**
- AI로 만든 초기 화면은 로그인 방식이나 사용자 흐름을 임의로 확정할 수 있으므로, 팀이 정한 요구사항을 기준으로 전체 화면의 일관성을 다시 검증해야 한다.
- 기능을 많이 설명하는 것보다 사용자가 이해하기 어려운 문구를 줄이고 핵심 행동과 상태 변화를 명확히 보여주는 것이 중요하다.
