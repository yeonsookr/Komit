# 스택별로 자주 나는 문제

프로젝트가 쓰는 기술을 알면 어디를 봐야 하는지가 정해진다. **정확도가 여기서 가장 크게 갈린다.**

해당하는 절만 읽는다. 쓰지 않는 기술의 절은 건너뛴다.

분류와 심각도는 다른 참고 파일의 기준을 그대로 쓴다. 여기서는 **어디를 어떻게 보는지**만 적는다.

---

## Next.js

바이브코딩에서 가장 많이 쓰인다.

### 1. 서버 동작에 인증 확인이 없다

화면에서만 부를 수 있다고 생각하기 쉬운데, 실제로는 밖에서 직접 부를 수 있다.

**볼 것** — 서버에서 도는 동작 하나하나에 "누가 불렀는지" 확인하는 코드가 있는가.

`보안 · 접근 제어`, 대개 `HIGH`.

### 2. 브라우저로 내려가는 환경변수에 비밀값

`NEXT_PUBLIC_` 으로 시작하는 환경변수는 **브라우저 코드에 그대로 박힌다.** 감춰지지 않는다.

**볼 것** — 그 접두어가 붙은 이름 중에 `KEY`, `SECRET`, `TOKEN`, `PASSWORD` 가 들어간 것이 있는가.

`보안 · 비밀 관리`, `HIGH`.

### 3. 요청을 받는 파일에 인증이 없다

`route.ts` 같은 요청 처리 파일마다 인증 확인이 있는지 본다. 미들웨어가 막고 있다고 해도, 막는 경로 목록과 실제 파일 경로가 어긋나는 일이 잦다.

**볼 것** — 미들웨어가 막는 경로 목록과 실제 요청 처리 파일 목록을 나란히 놓고 빠진 것을 찾는다.

`보안 · 접근 제어`.

### 4. 서버 전용 코드가 브라우저로 내려간다

데이터베이스를 직접 부르는 코드가 화면 쪽 파일에 섞여 들어간 경우.

**볼 것** — 브라우저에서 도는 표시가 붙은 파일에서 데이터베이스나 서버 전용 열쇠를 쓰는지.

`보안 · 비밀 관리`.

## Supabase

Next.js와 함께 가장 많이 쓰인다.

### 1. 표 단위 권한 설정 — 이 스택 최대 구멍

기본적으로 공개 열쇠만 있으면 표 전체를 읽을 수 있다. 표마다 권한을 켜 줘야 막힌다.

그런데 이 설정은 **코드가 아니라 서비스 화면에 있다.** 코드만 보고 켜졌는지 알 수 없다.

**그래서 이렇게 한다.**

1. 마이그레이션이나 정책 파일에 권한 설정이 있는지 찾는다
2. 있으면 어떤 표에 걸려 있는지 본다
3. **없으면 문제로 단정하지 않는다.** 「확인하지 못한 영역」에 넣고 물어볼 것으로 만든다

```
확인하지 못한 영역
  영역   데이터베이스의 표 단위 권한 설정
  이유   코드가 아니라 서비스 화면에 있는 설정이라 이 검사로는 볼 수 없다

물어볼 것
  문항   데이터베이스에서 표마다 권한을 켜 두셨나요?
  보기   켜 두었습니다 / 모르겠습니다 / 그게 뭔가요
  근거   이 설정이 꺼져 있으면 공개 열쇠만으로 표 전체를 읽을 수 있다.
         코드로는 확인할 수 없어 여쭙는다.
```

보기에 `그게 뭔가요` 를 넣는 이유 — 대부분의 의뢰인은 이 설정을 모른다. 모른다고 답할 자리가 있어야 솔직하게 답한다.

### 2. 관리 열쇠를 브라우저에서 쓴다

관리용 열쇠는 위의 권한 설정을 **전부 무시한다.** 브라우저 코드에 들어가면 그 자체로 전체가 열린다.

**볼 것** — `service_role` 이 든 환경변수를 어디서 쓰는지 따라간다. 화면 쪽 파일에서 쓰면 문제다.

`보안 · 비밀 관리`, `HIGH`.

### 3. 파일 저장소가 공개로 열려 있다

**볼 것** — 저장소 설정이 코드에 있으면 공개 여부를 본다. 없으면 「확인하지 못한 영역」에 넣는다.

## 그 밖의 스택

아래는 흔히 함께 쓰인다. 발견하면 참고한다.

| 기술 | 자주 나는 것 |
| --- | --- |
| Firebase | 접근 규칙이 모두 허용으로 열려 있음. 설정 파일을 본다 |
| Vercel · Netlify | 환경변수가 미리보기 환경까지 공유됨 |
| Prisma · Drizzle | 조건 없는 조회, 목록을 돌며 하나씩 조회 |
| Stripe · 토스페이먼츠 | 알림 서명 미확인, 금액을 화면에서 받음 |
| Clerk · Auth.js | 로그인은 붙였으나 자원 소유자 확인이 없음 |

여기에 없는 기술이면 일반 항목만으로 검사한다. **모르는 기술을 아는 척하지 않는다.**

---

## 스택을 알 수 없을 때

패키지 목록이나 설정 파일이 없어 무엇을 쓰는지 모르겠으면, 억지로 추측하지 않는다.

- 기술 목록을 비워 둔다
- 「확인하지 못한 영역」에 무엇을 몰라서 못 봤는지 적는다
- 일반 항목만으로 검사를 마친다
