# Komit 규칙서 (`RULES.md`)

Komit의 **정책 값과 불변식**을 모아 놓은 단일 출처다.

| 항목 | 내용 |
| --- | --- |
| 목적 | 화면·API 명세·코드에 흩어진 규칙을 한곳에서 관리한다 |
| 기준일 | 2026-09-19 |
| 관계 문서 | 기획서 `proposal.md`, 백엔드 `BACKEND_CONVENTIONS.md`, 프론트 `FRONTEND_CONVENTIONS.md` |

## 이 문서를 쓰는 법

- **숫자와 기한은 이 문서에만 둔다.** 기획서·API 명세·화면 문구는 값을 다시 적지 않고 규칙 번호를 인용한다.
- 규칙 번호는 바뀌지 않는다. 규칙이 사라지면 번호를 비워 두고 재사용하지 않는다.
- 값을 바꿀 때는 **영향 범위** 열에 적힌 곳을 모두 함께 고친다.
- 근거가 없는 규칙은 넣지 않는다. 정하지 못한 것은 맨 아래 「미확정」에 둔다.

### 결함 지문 (`R-SCAN-20`)

판이 바뀌어도 같은 문제를 같은 문제로 알아보기 위한 값이다. skill 담당자의
결과 스키마 `ai/komit-scan/schema/komit-result.schema.json` 의
`$defs.issue.fingerprint` 와 결과 예시
`ai/komit-scan/schema/komit-result.example.json` 의
`issues[].fingerprint` 설계를 구체화한다.

- 문제의 분류·유형·대상을 조합한다.
- 코드를 고치면 줄 번호가 밀릴 수 있으므로 줄 번호는 넣지 않는다.
- 모든 문제에 지문을 붙이고, 서버는 같은 지문을 이전 판의 같은 문제로 잇는다.
- 하위 분류, 대상 경로 범위, HTTP 메서드, 문자열 표준화 같은 세부 구성은
  「미확정」에서 별도로 관리한다.

### 마지막 설문의 구성 (`R-SCAN-14`)

| 종류 | 누가 정하는가 | 예 |
| --- | --- | --- |
| 고정 문항 | Komit | 예산과 기한이 정해져 있나요 |
| 만든 문항 | 검사 결과 | 실제 결제를 받을 계획인가요 · 기존 회원 데이터를 유지해야 하나요 |

만든 문항은 코드만으로 판정할 수 없는 것을 가리기 위한 것이다. (`R-SCAN-11`) 실제 결제를 받는지, 회원 데이터를 남겨야 하는지에 따라 적용되는 법이 달라지므로, 코드에서 그 기능을 찾았을 때만 묻는다.

문항 수를 제한하는 이유는 묻는 것이 많아지면 의뢰인이 끝까지 답하지 않기 때문이다.

### 점수 내는 법 (`R-SCAN-10`, `R-SCAN-18`)

두 단계로 낸다. 심각도별 건수를 세는 것이 전부라 누가 계산해도 같은 값이 나온다.

```
1. 가장 위험한 문제가 어느 구간인지 정한다
2. 그 구간의 시작 점수에서 건수만큼 깎는다
```

#### 1단계 — 구간 정하기 (`R-SCAN-18`)

| 있는 문제 | 구간 | 시작 점수 |
| --- | --- | --- |
| 높음이 하나라도 있다 | 0 – 49 | **49** |
| 높음은 없고 보통이 있다 | 50 – 79 | **79** |
| 낮음만 있다 | 80 – 100 | **100** |
| 하나도 없다 | — | **100** |

**점수를 정하는 것은 문제의 수가 아니라 가장 위험한 문제다.** 사소한 문제가 서른 건 있어도 위험한 것이 없으면 80점대에 머물고, 위험한 문제가 하나만 있어도 49점을 넘지 못한다.

#### 2단계 — 구간 안에서 깎기

| 구간 | 깎는 법 | 나올 수 있는 점수 |
| --- | --- | --- |
| 높음 있음 (49에서 시작) | 높음 한 건당 **−3**, 최대 −30<br>보통 한 건당 **−1**, 최대 −8<br>낮음은 깎지 않는다 | 11 – 49 |
| 보통까지 (79에서 시작) | 보통 한 건당 **−2**, 최대 −20<br>낮음 한 건당 **−1**, 최대 −6 | 53 – 79 |
| 낮음만 (100에서 시작) | 낮음 한 건당 **−2**, 최대 −12 | 88 – 100 |

각 구간에서 깎을 수 있는 양이 구간 폭보다 작아, **아무리 많아도 아래 구간으로 내려가지 않는다.** 구간이 판정이고 그 안의 숫자는 얼마나 갈 길이 먼지를 나타낸다.

#### 계산 예

```
높음 14건 · 보통 14건 · 낮음 2건

1. 높음이 있다        → 49에서 시작
2. 높음 14건 × 3 = 42 → 상한 30
   보통 14건 × 1 = 14 → 상한 8
   낮음은 깎지 않는다

49 − 30 − 8 = 11점  ·  지금 출시하면 위험합니다
```

#### 고쳐 나가면 이렇게 움직인다

| 남은 문제 | 점수 |
| --- | --- |
| 높음 14 · 보통 14 | 11 |
| 높음 7 · 보통 14 | 20 |
| 높음 3 · 보통 14 | 32 |
| 높음 1 · 보통 14 | 38 |
| **높음 0** · 보통 14 | **57** |
| 보통 5 | 67 |
| 보통 2 | 73 |
| 없음 | 100 |

사소한 것을 먼저 고쳐도 점수가 거의 오르지 않는다. **높음을 다 없애야 구간이 바뀌며 크게 오른다.** 무엇을 먼저 맡겨야 하는지가 점수로 드러난다.

### 점수 구간 (`R-SCAN-19`)

| 점수 | 판정 |
| --- | --- |
| 0 – 49 | 지금 출시하면 위험합니다 |
| 50 – 79 | 출시 전 정비가 필요합니다 |
| 80 – 100 | 출시할 수 있습니다 |

구간이 곧 색이고 구간이 곧 문장이다. 화면은 이 구간으로 점수 색을 정한다.
