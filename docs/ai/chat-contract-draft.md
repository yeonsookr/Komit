# 상담 채팅 기반 계약 초안 계약

## 1. 목적과 범위

무료 상담 채팅에서 합의한 내용을 계약 유형에 맞는 계약서 작성 화면의 초안으로 정리한다.
**AI가 만든 초안은 방마다 한 번만 만들어 서버에 보관한다.** 같은 방에서 다시 열면 보관해 둔
것을 그대로 돌려주므로 모델을 다시 부르지 않는다. 생성 결과는 개발자가 검토·수정한 뒤 기존
계약서 작성 API로 제출한다.

이 문서는 AI가 사용할 입력과 초안 작성 범위만 정한다. 채팅 저장·조회, 방 전환, 계약 저장,
권한 확인은 각각의 기존 담당 영역이 맡는다.

## 2. 입력

AI는 채팅 저장소를 직접 조회하지 않는다. 채팅 담당 영역이 무료 상담방 하나의 메시지를
작성 시각 순으로 정렬해 전달한다.

| 필드 | 의미 |
| --- | --- |
| `chatRefId` | 한 무료 상담방의 채팅 참조 키 |
| `authorRole` | 메시지 작성자의 역할. 의뢰인 또는 개발자 |
| `createdAt` | 메시지 작성 시각 |
| `content` | 메시지 본문 |

서로 다른 `chatRefId`의 메시지를 한 입력에 섞지 않는다. 새 상담은 같은 프로젝트와 개발자
조합이어도 새 `INQUIRY` 방과 새 `chatRefId`를 사용한다.

## 3. 실행 조건과 전달 경로

### 언제 만드나

갈래를 정하는 쪽은 의뢰인이고 초안을 받는 쪽은 개발자다. 두 동작은 시점이 다르다.

| 순서 | 누가 | 무엇을 | 초안 |
| --- | --- | --- | --- |
| 1 | 의뢰인 | 무료 상담방을 `CONSULTING` 또는 `DEVELOPMENT`로 전환 (`R-MATCH-03`) | 아직 만들지 않는다 |
| 2 | 개발자 | 새로 열린 방에서 계약서 작성 화면에 들어옴 | **여기서 만든다** |
| 3 | 개발자 | 초안을 검토·수정하고 일정·금액을 채워 제출 | 초안은 여기서 끝난다 |

- 전환이 성공하지 않으면 초안도 만들지 않는다. 진행하지 않기로 끝낸 상담이 그렇다.
- 이미 전환된 상담방은 기존 `ROOM_ALREADY_CONVERTED` 계약에 따라 다시 전환하지 않는다.
- AI가 계약서를 제출하거나 서명하지 않는다. 개발자가 초안을 검토·수정하고 기존 계약서 작성
  API를 호출한다.

### 어떻게 전달하나

`POST /rooms/{roomId}/contract-draft` — `roomId`는 갈래가 정해져 새로 열린 방이다.

| 항목 | 값 |
| --- | --- |
| 부르는 쪽 | 개발자의 계약서 작성 화면. 의뢰인은 부를 수 없다 (`403 FORBIDDEN`) |
| 응답 | 방의 갈래에 따라 `consulting` 또는 `development` 한쪽만 채운다. 나머지는 `null` |
| 저장 | AI 원본을 `contract_drafts`에 보관. **다시 불러도 모델을 다시 돌리지 않고 보관해 둔 것을 준다** |
| 갈래 전 | `409 ROOM_NOT_CONVERTED` — 아직 갈래를 정하지 않은 상담방 |
| 실패 | `502 AI_RESPONSE_INVALID`(계약에 안 맞는 결과) · `503 AI_SERVICE_UNAVAILABLE`(생성 서비스 연결 불가) |

초안은 개발자가 본다. 제외 사유처럼 개발자가 다듬어야 할 문구가 들어 있어 의뢰인에게 먼저
보이지 않는다. 그래서 전환 응답에 실어 보내지 않는다.

### 어디에 보관하나

**AI 원본은 서버가, 개발자 수정분은 화면이 보관한다.** 나누는 기준은 다시 만들 수 있느냐다.
AI 원본은 모델을 다시 불러야 하므로 비용이 들고 같은 문장이 나온다는 보장도 없다. 개발자
수정분은 개발자가 다시 칠 수 있다.

| 무엇 | 어디 | 왜 |
| --- | --- | --- |
| AI가 만든 초안 원본 | 서버 (`contract_drafts`) | 다시 부르면 비용이 들고 문장이 달라진다 |
| 개발자가 고친 내용 | 화면 | 서버가 들고 있을 이유가 없다. 제출하면 계약 테이블로 간다 |

`contract_drafts` — 방 하나에 초안 하나.

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `id` | `INT` PK | |
| `room_id` | `INT` UNIQUE NOT NULL | 갈래가 정해져 새로 열린 방 |
| `contract_type` | `VARCHAR(50)` NOT NULL | 방의 갈래를 따른다 |
| `content` | `JSONB` NOT NULL | AI가 만든 초안. **한 번 쓰고 바꾸지 않는다** |
| `created_at` | `TIMESTAMPTZ` NOT NULL | |

- 개발자 수정분을 이 행에 덮어쓰지 않는다. 덮어쓰면 AI가 원래 뭐라고 했는지 사라진다.
- 계약서를 제출하면 내용은 계약 테이블로 옮겨 간다. 초안 행은 그때 역할이 끝난다.
- `content`를 작업·확인 문장·제외 요구사항 테이블로 쪼개지 않는다. 쪼개면 계약 테이블의
  복제본이 셋 더 생기고, 제출 전까지는 아무도 그 행들을 조회하지 않는다.

**이 표는 아직 ERD에 없다.** ERD 담당 확인 전까지 엔티티를 만들지 않는다. 화면 쪽 보관 방식은
`fe` 범위에서 정한다.

## 4. 컨설팅 계약 초안

기존 `WriteConsultingContractRequest`를 유지한다.

| 구분 | 필드 | 처리 |
| --- | --- | --- |
| AI 초안 | `topic` | 채팅에서 합의한 세션 주제를 한 줄로 정리 |
| AI 초안 | `detail` | 합의한 상담 내용의 상세 설명. 근거가 없으면 비움 |
| 개발자 입력 | `scheduledAt` | 세션 일시 |
| 개발자 입력 | `durationMinutes` | 세션 시간 |
| 개발자 입력 | `price` | 세션 금액 |
| 개발자 입력 | `message` | 계약서와 함께 보낼 전달 메시지 |

AI는 채팅에 등장한 일정·시간·금액을 자동 확정하지 않는다. 이 값은 개발자가 계약서를
작성하면서 직접 입력한다.

## 5. 개발 계약 초안

기존 `WriteDevelopmentContractRequest`를 유지한다.

| 구분 | 필드 | 처리 |
| --- | --- | --- |
| AI 초안 | `issueIds` | 맡기로 합의한 기존 요구사항 식별자 후보 |
| AI 초안 | `milestones[].title` | 합의한 작업 범위의 작업명 |
| AI 초안 | `milestones[].qaCriteria` | 의뢰인이 직접 확인할 수 있는 확인 문장 |
| AI 초안 | `rejectedIssues` | 맡지 않기로 한 요구사항과 채팅에서 확인된 사유 |
| 개발자 입력 | `startDate`, `dueDate` | 착수일과 최종 납기일 |
| 개발자 입력 | `freeRepairDays` | 무상 하자보수 기간 |
| 개발자 입력 | `milestones[].price` | 작업별 금액 |
| 개발자 입력 | `milestones[].workDate` | 작업별 참고 기간 |
| 개발자 입력 | `deliverableTitles` | 인계물 목록 |
| 개발자 입력 | `detail`, `message` | 계약 상세와 전달 메시지 |

AI는 입력으로 받은 기존 요구사항 안에서만 `issueIds`와 `rejectedIssues[].issueId`를 고른다.
존재하지 않는 식별자를 만들지 않는다. 제외 사유가 채팅에 없으면 임의로 작성하지 않는다.
확인 문장은 `R-REQ-01`, `R-REQ-04`, `R-QA-01`, `R-QA-05`를 따른다.

## 6. 출력 검증과 실패 처리

- 컨설팅과 개발 계약의 필드를 서로 섞지 않는다.
- 기존 계약서 작성 요청에 없는 필드를 추가하지 않는다.
- 채팅에 없는 합의·작업·제외 사유를 만들어내지 않는다.
- 필수 정보를 AI가 채우지 않는 필드로 남겨 둔 초안은 개발자가 입력을 마치기 전까지 제출하지
  않는다.
- AI 출력이 형식 검증에 실패하면 빈 계약서를 대신 제출하지 않고 초안 생성을 실패로 처리한다.

## 7. 현재 계약에서 바꾸지 않는 것

- `rooms`, 계약, 요청서 관련 ERD를 변경하지 않는다. 초안은 `contract_drafts`(`3절`)에만
  들어가고 기존 테이블에 컬럼을 더하지 않는다.
- 기존 응답에 무료 상담 요약용 상태·필드를 덧붙이지 않는다. 초안은 전용 엔드포인트(`3절`)로만
  내려가고, 방·계약 조회 응답은 그대로 둔다.
- `POST /rooms/{roomId}/consulting-contracts`와
  `POST /rooms/{roomId}/development-contracts`의 요청·응답 형식을 변경하지 않는다.
- 계약 저장, 수정, 서명과 체결 이후 불변 조건은 기존 계약 API와 `R-CON-01`~`R-CON-07`을
  그대로 따른다.
