# 요청서 변경 유형 계약

## 1. 목적과 적용 범위

컨설팅 세션 요약에서 요청서에 반영할 변경 후보를 `UPDATE`와 `ADD`로 구분한다. 이 계약은
컨설팅 세션이 끝난 뒤 생성하는 `changes`에 적용하며, 무료 상담 채팅에서 만드는 계약서 초안과
구분한다.

AI는 변경 후보를 제안할 뿐 요청서를 직접 변경하지 않는다. 사용자가 선택한 후보만 기존 변경
반영 API를 통해 적용한다.

## 2. AI 로컬 출력

AI가 생성하고 로컬에서 검증할 후보는 다음 필드만 가진다.

| 필드 | 형식 | 의미 |
| --- | --- | --- |
| `kind` | `UPDATE \| ADD` | 기존 요구사항 수정 또는 새 요구사항 추가 |
| `issueId` | 정수 또는 `null` | `UPDATE` 대상 요구사항. `ADD`이면 `null` |
| `title` | 문자열 | 반영할 요구사항 문장 |
| `detail` | 문자열 또는 `null` | 변경 이유 또는 보충 설명 |

`changeId`와 `isApplied`는 저장·반영 상태이므로 AI가 생성하지 않는다.

## 3. 유형별 불변식

### UPDATE

- 이미 요청서에 존재하는 요구사항을 수정할 때만 사용한다.
- `issueId`는 필수다.
- 대상은 AI 입력으로 제공된 기존 요구사항 목록 안에서만 고른다.
- Service는 실제 반영 전에 요구사항의 존재 여부와 소유권을 다시 확인한다.

```json
{
  "kind": "UPDATE",
  "issueId": 312,
  "title": "회원탈퇴 데이터는 30일 보관 후 삭제",
  "detail": "컨설팅에서 보관 기간을 합의했습니다."
}
```

### ADD

- 요청서에 없던 새 요구사항을 추가할 때만 사용한다.
- `issueId`는 반드시 `null`이다.
- AI가 새 요구사항의 DB 식별자를 만들지 않는다.

```json
{
  "kind": "ADD",
  "issueId": null,
  "title": "결제 실패 로그 수집",
  "detail": "코드 수정 전에 재현 로그를 수집합니다."
}
```

다음 조합은 거절한다.

- `UPDATE`와 `issueId=null`
- `ADD`와 기존 `issueId`
- 허용되지 않은 `kind`
- 빈 `title`
- 입력에 없는 `issueId`를 가리키는 `UPDATE`

## 4. 저장 후 Service 응답

Service가 후보를 저장하면 기존 `SummaryChangeResponse` 형태로 반환한다.

| 필드 | 소유 주체 | 의미 |
| --- | --- | --- |
| `changeId` | Service | 저장된 변경 후보 식별자 |
| `kind` | 검증된 AI 후보 | `UPDATE` 또는 `ADD` |
| `issueId` | 검증된 AI 후보 | 수정 대상 또는 `null` |
| `title` | 검증된 AI 후보 | 반영할 요구사항 문장 |
| `detail` | 검증된 AI 후보 | 변경 이유 또는 보충 설명 |
| `isApplied` | Service | 요청서 반영 여부 |

```json
{
  "changeId": 1,
  "kind": "UPDATE",
  "issueId": 312,
  "title": "회원탈퇴 데이터는 30일 보관 후 삭제",
  "detail": "컨설팅에서 보관 기간을 합의했습니다.",
  "isApplied": false
}
```

## 5. 생성과 검증 방식

MVP에서는 GMS가 구조화한 JSON을 스키마로 검증한다. 잘못된 조합을 조용히 고치거나
`UPDATE`를 `ADD`로 바꾸지 않고 생성 실패로 처리한다.

SetFit은 현재 구현 범위가 아니다. 실제 상담 문장에 목표 라벨을 사람이 붙인 데이터와 승인된
평가셋이 충분히 쌓인 뒤 별도 Jira에서 GMS 방식과 비교한다. 정확도뿐 아니라 `UPDATE` 대상을
놓치거나 새 요구사항을 기존 요구사항으로 잘못 덮어쓰는 오류를 함께 평가하고, 현재 방식보다
나은 결과가 확인될 때만 전환한다.

STT 음성·개발 용어 자료와 요구사항-확인 문장 데이터는 이 변경 유형 분류의 학습 데이터로
사용하지 않는다.

## 6. 변경하지 않는 것

- 기존 `SummaryChangeResponse` 필드를 추가하거나 이름을 바꾸지 않는다.
- 요청서 반영 API와 DB 구조를 변경하지 않는다.
- `changeId`와 `isApplied`를 AI 출력에 포함하지 않는다.
- 사용자의 선택 없이 변경 후보를 요청서에 자동 반영하지 않는다.
