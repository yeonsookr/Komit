# Komit 기획서

| 항목 | 내용 |
| --- | --- |
| 제품 | 바이브코딩 결과물의 출시 전 진단과 개발 위탁 중개 플랫폼 |
| 기준일 | 2026-09-11 |
| 핵심 가치 | 출시 가능 여부를 점검하고, 필요한 문제만 개발자에게 맡기며, 합의한 기준에 따라 안전하게 대금을 지급한다 |
| 플랫폼 역할 | 의뢰인과 개발자를 연결하고 계약·검수·지급 흐름을 기록하는 중개자 |

---

## 1. 제품 정의

Komit은 바이브코딩으로 서비스를 만들었지만 출시 준비도와 문제 해결 방법을 판단하기 어려운 사용자를 위한 플랫폼이다.

사용자는 자신의 개발 환경에서 프로젝트를 점검하고, 결과 파일만 Komit에 업로드한다. Komit은 결과를 이해하기 쉬운 이슈와 확인 기준으로 정리한다. 사용자는 직접 고칠 문제와 개발자에게 맡길 문제를 선택하고, 선택한 범위만 요청서와 계약으로 이어간다.

제품의 핵심 흐름은 다음 세 가지다.

1. **사전점검**: 프로젝트 상태를 진단하고 이슈와 QA 기준을 만든다.
2. **개발자 매칭**: 이슈를 바탕으로 상담·컨설팅·개발을 요청한다.
3. **계약과 안전거래**: 범위·금액·기한을 합의하고, 전체 작업 검수가 끝나면 계약 대금을 한 번에 정산한다.

---

## 2. 해결하려는 문제

바이브코딩 사용자는 기능을 만드는 데는 성공해도 다음 단계에서 막히기 쉽다.

- 지금 출시해도 되는지 판단하기 어렵다.
- 오류나 보안 문제를 개발자에게 설명하기 어렵다.
- 외주 범위와 완료 기준을 구체적으로 합의하기 어렵다.
- 결과물을 검수할 기준이 없어 대금 지급 시 분쟁이 생긴다.

Komit은 진단 결과를 **이슈 → 요청서 → 마일스톤별 QA → 전체 작업 최종 검수 → 일괄 정산**으로 연결해, 처음 발견한 문제와 실제 계약·검수 기준이 끊기지 않게 한다.

## 3. 사용자와 역할

| 사용자 | 주요 목적 | 주요 기능 |
| --- | --- | --- |
| 의뢰인 | 만든 서비스를 출시하고 필요한 작업을 맡긴다 | 사전점검, 이슈 선택, 개발자 탐색, 상담·계약, 검수, 리뷰 |
| 개발자 | 자신의 전문성과 가격을 제시하고 작업을 수행한다 | 프로필·경력·포트폴리오 관리, 상담, 제안, 마일스톤 수행, 정산 |
| 운영자 | 거래 흐름과 예외 상황을 관리한다 | 검사 항목 관리, 신고 확인, 정산·대사, 미결 거래 처리 |

한 계정은 의뢰인과 개발자 역할을 함께 가질 수 있으며, 화면에서 역할을 전환한다.

## 4. 핵심 사용자 흐름

```text
프로젝트 등록
→ 사전 문진
→ 사용자 개발 환경에서 검사 실행
→ 결과 파일 업로드
→ 추가 질문 답변
→ 진단서·이슈·QA 기준 확정
→ 맡길 이슈 선택
→ 요청서 생성
→ 개발자 탐색 및 상담
→ 개발자의 범위·금액·기한 제안
→ 양측 합의·서명
→ 대금 예치
→ 마일스톤 수행
→ 마일스톤별 QA 확인
→ 전체 작업 완료 및 최종 검수
→ 계약 대금 일괄 정산
→ 정산 및 리뷰
```

와이어프레임의 주요 내비게이션은 `의뢰`, `개발자 찾기`, `사전점검`, `정산`으로 구성한다. 마이페이지에서는 계정, 등록 프로젝트, 개발자 프로필, 알림과 약관을 관리한다.

## 5. 핵심 기능

### 5.1 사전점검

- 4단계 문진으로 프로젝트 종류, 현재 운영 단계, 어려움과 목표를 확인한다.
- 검사는 사용자가 이미 사용하는 AI 코딩 도구에서 실행한다.
- 소스 코드는 사용자 컴퓨터 밖으로 보내지 않고, 검사 결과 파일만 업로드한다.
- 결과에는 출시 준비도, 발견 이슈, 근거 위치, 검사한 범위와 검사하지 못한 범위를 표시한다.
- 코드만으로 판단할 수 없는 내용은 추가 질문으로 확인한다.
- 재진단할 때는 이전 이슈와 해결 여부를 이어서 추적한다.

### 5.2 이슈와 요청서

- 발견된 문제 하나를 이슈 하나로 관리한다.
- 각 이슈에는 의뢰인이 직접 실행할 수 있는 QA 기준을 붙인다.
- 의뢰인이 선택한 이슈만 요청서에 포함한다.
- 직접 해결한 이슈는 해결 처리하고, 개발을 맡긴 이슈는 계약과 마일스톤으로 연결한다.
- 개발자가 별도로 제안한 작업도 마일스톤으로 추가할 수 있다.

### 5.3 개발자 탐색과 상담

- 개발자 목록을 작업 분야와 기술 역량으로 탐색한다.
- 개발자 프로필에서 소개, 경력, 기술, 포트폴리오, 리뷰, 상담·컨설팅·개발 상품을 확인한다.
- 평가는 **개발 실력**과 **설명력**을 나누어 보여준다.
- 상담은 무료 채팅이며 여러 개발자에게 요청할 수 있다.
- 컨설팅은 예약된 세션으로 진행하고, 개발 가격과 일정은 개발자가 제안한다.
- 프로젝트와 개발자 조합별로 상담·컨설팅·개발 대화방을 구분한다.

### 5.4 계약과 변경 합의

- 계약은 협의, 합의, 서명 순서로 진행한다.
- 의뢰인과 개발자의 승인·서명을 각각 기록하며, 양측 확인 전에는 계약이 성립하지 않는다.
- 개발계약은 여러 마일스톤으로 구성하고 각 마일스톤에 작업 범위, 기한, QA 기준을 둔다. 계약 금액은 전체 작업 기준으로 합의한다.
- 금액, 기간, QA 기준, 추가 작업이 바뀌면 특약으로 남기고 양측이 각각 승인한다.
- 특약은 원본 이슈를 덮어쓰지 않고 변경 이력으로 연결한다.

### 5.5 검수·지급·리뷰

- 개발자가 완료를 보고하면 의뢰인이 마일스톤의 QA 기준을 직접 확인한다.
- 모든 기준을 통과한 마일스톤만 완료 처리한다.
- 마일스톤 완료 여부는 진행 상황과 최종 검수를 위한 기준으로 사용하며, 중간 대금은 지급하지 않는다.
- 모든 마일스톤이 완료되고 의뢰인이 최종 검수하면 완료 결과를 Escrow 서비스에 전달해 계약 대금 전액을 한 번에 정산한다.
- 예치금은 계약 취소·환불 정책에 따라 처리한다.
- 거래 종료 후 의뢰인은 개발 실력과 설명력을 평가하고 리뷰를 남길 수 있으며, 개발자는 답글을 작성할 수 있다.

---

## 6. 안전거래 원칙

1. **계약 범위를 명확히 한다.** 선택한 이슈와 합의된 추가 작업만 계약 범위로 본다.
2. **완료 기준을 행동으로 쓴다.** 비개발자도 직접 확인할 수 있고 통과 여부가 명확한 문장으로 만든다.
3. **전체 완료와 정산을 연결한다.** 마일스톤별로 진행 상황을 검수하되, 모든 작업이 끝난 뒤 계약 대금을 한 번에 정산한다.
4. **변경 이력을 보존한다.** 원본 합의와 이후 특약을 분리해 기록한다.
5. **자금 처리를 분리한다.** Komit은 계약·마일스톤·QA를, Escrow는 예치·지급·환불을 담당한다.
6. **판단자가 되지 않는다.** 신고나 분쟁이 생기면 기록과 근거를 정리하되, Komit이 법적 판단·조정·중재를 하지 않는다.

## 7. 서비스 경계

| 구분 | 담당 영역 |
| --- | --- |
| Komit | 사용자·개발자, 프로젝트, 진단, 이슈, QA 기준, 요청서, 대화방, 계약, 마일스톤, 특약, 리뷰, 신고 |
| Escrow | 계좌 확인, 예치, 지급, 환불, 거래 원장, 외부 금융 연동, 대사, 운영 감사 기록 |

Escrow는 Komit과 분리된 서비스로 운영한다. 동일 요청의 중복 처리를 막고, 외부 금융 결과와 내부 원장 기록이 일치하는지 확인한 뒤 거래를 완료한다.

---

## 8. 정책

- 사전점검과 기본 상담은 무료다.
- 컨설팅과 개발 가격은 개발자가 제안한다.
- 플랫폼 수익은 전체 작업이 완료되어 일괄 정산된 거래에 대한 중개 수수료로 한다.
- 와이어프레임에 표시된 개별 금액과 시간은 예시이며 확정 정책이 아니다.
- 개인정보와 계좌 정보는 필요한 범위에서만 다루고, 민감 정보는 화면과 로그에서 마스킹한다.
