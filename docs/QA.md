# Komit QA 문서

## 1. 문서 목적

이 문서는 [`FUNCTIONAL_SPEC.md`](FUNCTIONAL_SPEC.md)에 정의된 기능의 구현 범위와 품질 검증 기준을 설명합니다. 정책 값과 불변식은 [`RULES.md`](RULES.md)를 기준으로 합니다.

## 2. 표기 기준

| 표기 | 의미 |
| --- | --- |
| **제공** | 사용자 화면과 실제 서비스가 연결되어 검증할 수 있음 |
| **부분 제공** | 주요 기능은 있으나 일부 사용자 단계 또는 연동이 제한됨 |
| **시연 전용** | 화면 시연은 가능하지만 실제 서비스의 영속 처리 범위가 아님 |
| **미제공** | 현재 제공 및 검증 범위에 포함되지 않음 |
| **PASS** | 기대 결과를 확인함 |
| **FAIL** | 기대 결과와 다르거나 필수 조건을 위반함 |
| **BLOCKED** | 외부 시스템 또는 시험 환경 문제로 실행하지 못함 |
| **N/A** | 현재 제공 범위가 아니어서 시험하지 않음 |

## 3. 기능 제공 범위

| 영역 | 기능 | 범위 | 비고 |
| --- | --- | --- | --- |
| 회원 | 로그인·약관·가입·회원 계좌 | 제공 | 가입 완료 조건 포함 |
| 회원 | 프로필·개발자 프로필·포트폴리오 | 제공 | 공개 프로필 제공 |
| 회원 | 알림 목록·읽음 처리 | 시연 전용 | FE와 Mock API는 있으나 Service API는 없음 |
| 진단 | 문진·로컬 검사·결과 업로드·추가 질문 | 제공 | 소스 코드는 서버에 전송하지 않음 |
| 진단 | 준비도·이슈·재진단 연결 | 제공 | 회차별 문제 연결 |
| 요청서 | 이슈 선택·직접 요구사항 추가·QA 문장 편집 | 제공 | 기존 요구사항의 제목·설명은 편집하지 않음 |
| 매칭 | 개발자 탐색·추천·상담 요청 | 제공 | 추천 근거 포함 |
| 무료 상담 | 채팅·거래 유형 선택 | 제공 | WebRTC·STT 미사용 |
| 계약 | AI 최초 초안·편집·전송·서명 | 제공 | 한쪽 서명 뒤 수정 금지 |
| 계약 | 편집 중 작업별 AI QA 후보 추천 | 제공 | 개발자 전용, 기존 작업과 새 작업 모두 지원 |
| 결제 | 예치·허용 시 취소 환불 | 제공 | Escrow 연동 |
| 컨설팅 | 예약·동의·WebRTC·녹음·STT·요약 | 제공 | 유료 컨설팅 전용 |
| 컨설팅 | 자동 지급 | 부분 제공 | 스케줄러와 지급 처리는 있으나 사용자의 신고 생성 API가 없어 지급 차단 전체 흐름은 연결되지 않음 |
| 컨설팅 | 요약 후보의 요청서 반영 | 시연 전용 | FE와 Mock API는 있으나 Service 반영 API는 없음 |
| 개발 외주 | 계약 체결·예치 | 제공 | 계약 단계까지 |
| 개발 외주 | 착수·작업별 완료 확인·QA 판정 | 제공 | 돌아온 작업 재요청과 무응답 자동 통과 포함 |
| 개발 외주 | 인계 자료 등록·최종 인수 시험 | 제공 | 요청한 뒤에는 자료를 바꾸지 않음 |
| 개발 외주 | 전액 지급·지급 후 해금 파일 다운로드 | 제공 | 지급액과 수수료가 모두 확정돼야 개방 |
| 리뷰 | 완료 거래 리뷰·평점·답글 | 제공 | 작성 자격 검증 |
| 신고 | 사용자 신고·운영자 처리 | 시연 전용 | FE와 Mock API는 있으나 Service 생성·처리 API는 없음 |
| 파일 | 업로드·완료·읽기 URL | 제공 | 저장소 직접 전송 |
| Escrow | 계좌·예치·지급·환불·원장·대사 | 제공 | 별도 자금 서비스 |

## 4. 시험 환경

### 4.1 필수 구성

- Komit 웹, Service, Escrow, AI Worker
- Service PostgreSQL, Escrow PostgreSQL, MongoDB, Redis, MinIO
- WebRTC 검증용 브라우저 또는 기기 2대
- SSAFY 금융 API 시험 환경
- AI 생성 API와 STT 작업 환경

### 4.2 시험 사용자

| 사용자 | 조건 |
| --- | --- |
| 의뢰인 A | 가입·약관·회원 계좌 준비 완료 |
| 개발자 B | 개발자 프로필과 수령 계좌 준비 완료 |
| 제3자 C | 권한 차단 시험용 계정 |

## 5. 핵심 사용자 시나리오

### QA-E2E-01 사전점검에서 요청서까지

| 항목 | 내용 |
| --- | --- |
| 절차 | 프로젝트 등록 → 문진 → 로컬 검사 → 결과 업로드 → 추가 질문 → 진단 → 이슈 선택 → 요청서 저장 |
| 기대 결과 | 소스 코드는 서버에 올라가지 않고 결과 파일만 처리됩니다. 선택한 이슈만 요청서에 포함됩니다. |
| 예외 시험 | 다른 진단의 결과, 잘못된 형식, 버전 불일치와 빈 요구사항을 거부합니다. |

### QA-E2E-02 요청서의 QA 확인 문장

| 항목 | 내용 |
| --- | --- |
| 절차 | 요청서 수정 → 요구사항별 QA 문장 추가·수정·삭제 → 요청서 저장 |
| 기대 결과 | 의뢰인이 저장한 문장만 요청서에 남고 이후 개발계약의 초기 완료 기준으로 전달됩니다. |
| 예외 시험 | 빈 요청서, 허용 길이를 넘긴 문장과 계약에 사용된 요구사항 제외를 거부합니다. |

### QA-E2E-03 개발자 선택과 무료 상담

| 항목 | 내용 |
| --- | --- |
| 절차 | 탐색 또는 추천 → 무료 상담 요청 → 양측 채팅 → 의뢰인이 거래 유형 선택 |
| 기대 결과 | 무료 상담은 채팅만 사용하며, 선택 뒤 문의방이 종료되고 새 거래 방이 생성됩니다. |
| 예외 시험 | 제3자 접근과 개발자의 거래 유형 선택을 거부합니다. |

### QA-E2E-04 AI 계약 초안과 협의

| 항목 | 내용 |
| --- | --- |
| 절차 | 개발자가 계약서 작성 선택 → AI 초안 → 값 입력 → 전송 → 수정 협의 → 재전송 |
| 기대 결과 | 작성 화면에서 최초 한 번 생성하고 이전 무료 상담을 사용하며 수정 시 AI 초안으로 덮어쓰지 않습니다. |
| 예외 시험 | AI 시간 초과, 잘못된 출력, 요청 범위 혼입과 동일 방 재호출을 확인합니다. |

### QA-E2E-05 계약 편집 중 AI QA 추천

| 항목 | 내용 |
| --- | --- |
| 절차 | 개발자가 개발계약 편집 → 작업의 `AI 확인 문장 추천` 선택 → 후보 3개 확인 → 필요한 후보 반영 → 계약 전송 |
| 기대 결과 | 기존 요구사항 작업은 식별자와 현재 제목·설명을 사용하고, 새 작업은 저장 전 현재 제목·설명을 사용하여 후보를 만듭니다. 후보를 고르기 전에는 계약에 저장하지 않습니다. |
| 예외 시험 | 의뢰인·제3자의 요청, 다른 프로젝트 요구사항, 취소되었거나 한쪽이 서명하여 잠긴 계약, 빈 작업 제목을 거부합니다. |

| 예외 시험 | 중복·제3자 서명, 금액 변조와 같은 예치 요청 재전송을 확인합니다. |

| 기대 결과 | 계약 성립과 양측 동의 뒤 시작하고 직접 연결 실패 시 TURN을 이용합니다. |

### QA-E2E-08 녹음·전사·요약

| 항목 | 내용 |
| --- | --- |
| 절차 | 통화 → 각자 마이크 녹음 → 종료 → 업로드 → 전사 → 요약 조회 |
| 기대 결과 | 동의 이전 음성은 담지 않고 화자별 녹음을 구분하며 근거가 연결된 요약을 제공합니다. |
| 예외 시험 | 녹음 누락, 잘못된 파일, 중복 결과, 범위 밖 근거와 AI 실패를 확인합니다. |

### QA-E2E-09 컨설팅 정산

| 항목 | 내용 |
| --- | --- |
| 절차 | 이의 기간 전 확인 → 기간 후 정산 → 같은 계약의 동시 지급 실행 |
| 기대 결과 | 조건 충족 전에는 지급하지 않고, 충족 뒤 한 번만 이체하고 원장에 기록합니다. |
| 예외 시험 | 지급 차단 사유, 계좌 없음, 금액 불일치와 금융망 결과 불명을 확인합니다. |

### QA-E2E-10 리뷰

| 항목 | 내용 |
| --- | --- |
| 절차 | 완료 거래 평가 제출 → 평점 확인 → 개발자 답글 |
| 기대 결과 | 리뷰가 한 번 저장되고 평점에 반영되며 해당 개발자만 답글을 작성합니다. |
| 예외 시험 | 미완료 거래, 제3자, 중복 리뷰와 잘못된 점수를 거부합니다. |

### QA-E2E-11 개발 착수와 작업별 완료 확인

| 항목 | 내용 |
| --- | --- |
| 절차 | 양측 서명·예치 확인 → 개발자 착수 → 1차 작업 완료 확인 요청 → 의뢰인이 QA 확인 문장별로 판정 |
| 기대 결과 | 예치가 끝나야 착수하고, 모든 확인 문장을 충족한 작업만 통과합니다. 일부만 통과시키면 작업이 개발자에게 돌아가고 양쪽 화면에 돌아온 것으로 표시합니다. (`R-CON-24`, `R-QA-01`) |
| 예외 시험 | 예치 전 착수, 제3자 요청, 통과한 작업의 재요청, 돌아온 작업의 기한 재계산을 확인합니다. |

### QA-E2E-12 무응답 자동 통과

| 항목 | 내용 |
| --- | --- |
| 절차 | 완료 확인 요청 → 의뢰인 무응답 → 기한 경과 |
| 기대 결과 | 기한이 지나면 자동 통과하고, 돌아온 작업은 다시 요청할 때까지 자동 통과를 세지 않습니다. (`R-QA-02`) |
| 예외 시험 | 기한 직전 거부, 거부 뒤 재요청, 같은 작업의 중복 자동 통과를 확인합니다. |

### QA-E2E-13 인계 자료 등록과 최종 인수 시험

| 항목 | 내용 |
| --- | --- |
| 절차 | 일반 작업 전부 통과 → 산출물에 인수시험용 URL·파일과 해금 파일 등록 → 최종 인수 시험 요청 → 의뢰인 확인·통과 |
| 기대 결과 | 계약 전체에 시험 자료와 해금 파일이 하나 이상 있어야 요청할 수 있고, 요청한 뒤에는 자료를 바꾸지 않습니다. 인계 작업은 계약마다 하나이고 그 통과가 최종 인수 시험 통과입니다. (`R-QA-03`, `R-QA-06`) |
| 예외 시험 | 일반 작업이 남은 상태의 요청, 시험 자료나 해금 파일이 없는 요청, 요청 뒤 자료 변경, 제3자 통과를 거부합니다. 되돌릴 수 없다는 확인창과 등록이 닫힌 까닭이 화면에 보이는지 확인합니다. |

### QA-E2E-14 개발 계약 전액 지급과 해금

| 항목 | 내용 |
| --- | --- |
| 절차 | 최종 인수 시험 통과 → Escrow 전액 정산 → 지급액·수수료 확정 → 계약 완료 → 해금 파일 다운로드 |
| 기대 결과 | 마일스톤 분할 없이 한 번에 지급하고, 지급액과 수수료가 모두 확정돼야 완료로 바꿉니다. 그때부터 리뷰를 쓸 수 있고 의뢰인이 해금 파일을 받습니다. (`R-PAY-01`, `R-PAY-07`, `R-PAY-14`) |
| 예외 시험 | 개발자 수령 계좌 없음, 금융망 결과 불명, 같은 계약의 동시 지급 요청을 확인합니다. 지급 처리 중에는 확인 탭·방 머리·진행 탭이 처리 중으로 보이고 다시 읽어 완료로 바뀌는지 봅니다. |

### QA-E2E-15 인계 파일 다운로드 권한

| 항목 | 내용 |
| --- | --- |
| 절차 | 지급 전 의뢰인이 시험 파일·해금 파일 요청 → 지급 후 해금 파일 요청 → 개발자가 자기 파일 요청 |
| 기대 결과 | 시험 파일은 지급 전에도 받고, 해금 파일은 지급이 확정된 뒤에만 받습니다. 개발자는 자기가 올린 파일을 언제든 받습니다. 받지 못하면 서버가 준 사유를 화면에 알립니다. (`R-QA-06`) |
| 예외 시험 | 지급 전 해금 파일 요청, 제3자 요청, 없는 파일 식별자를 거부합니다. |
