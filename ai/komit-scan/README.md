# komit-scan

바이브코딩으로 만든 서비스가 **지금 출시해도 되는 상태인지** 검사한다.

의뢰인이 쓰던 AI 코딩 도구에서 자기 컴퓨터로 검사하고, 결과 파일만 Komit에 올린다. **소스 코드는 컴퓨터 밖으로 나가지 않는다.**

---

## 무엇을 보는가

| 분류 | 보는 것 |
| --- | --- |
| 위법 | 개인정보처리방침·이용약관·환불 안내·판매자 정보·회원탈퇴 경로 |
| 보안 | 접근 제어·비밀 관리·입력 처리·인증과 세션·설정·개인정보 암호화 |
| 결제 | 금액 정합성·승인 흐름·중복 결제·알림 검증 |
| 데이터 | 유실 위험·되돌릴 수 없는 삭제·구조 기록 |
| 비용 | 상한 없는 외부 호출·과다 조회 |
| 인계 | 실행 방법·환경변수 목록·다른 컴퓨터에서 실행 가능한지 |
| AI 잔재 | 없는 것을 부르는 코드·중복 구현·만들다 만 자리 |
| 기타 | 오류 처리·기록 장치·환경 분리·반응형 |

검사 기준 전문은 [`skills/komit-scan/`](skills/komit-scan/) 에 있다. **누구나 열어서 무엇을 검사하는지 읽을 수 있다.** 자기 코드에 무엇을 시키는지 모르는 채로 돌리지 않아도 된다.

---

## 쓰는 법

### Claude Code

```
/plugin marketplace add <저장소 주소>
/plugin install komit-scan@komit
```

설치한 뒤 프로젝트에서 검사를 요청한다.

### Cursor · Codex · 그 외

Komit에서 검사 파일을 내려받아 프로젝트에 넣고, 안내된 문장을 그대로 입력한다.

### 이 저장소에서 바로 써 보려면

스킬을 이 저장소의 Claude Code 설정 폴더로 복사한다.

```bash
cp -r ai/komit-scan/skills/komit-scan .claude/skills/
```

복사본은 `.gitignore` 에 들어 있어 커밋되지 않는다. **원본은 `ai/komit-scan/skills/` 하나뿐이다.** 지시문을 고치면 원본을 고치고 다시 복사한다.

시험용 프로젝트에 돌려 보려면 [`fixtures/README.md`](fixtures/README.md) 를 본다.

## 결과 파일

검사가 끝나면 아래 내용을 담은 파일이 만들어진다.

| 항목 | 내용 |
| --- | --- |
| 런칭 준비도 | 0~100점. 구간이 곧 판정이다 |
| 발견한 문제 | 분류·심각도·파일 경로와 줄 번호 |
| 물어볼 것 | 코드만으로 판정할 수 없어 의뢰인에게 묻는 문항 |
| 확인한 영역 | 실제로 본 곳 |
| 확인하지 못한 영역 | 못 본 곳과 그 이유 |

| 점수 | 판정 |
| --- | --- |
| 0 – 49 | 지금 출시하면 위험합니다 |
| 50 – 79 | 출시 전 정비가 필요합니다 |
| 80 – 100 | 출시할 수 있습니다 |

---

## 지키는 것

- **위치를 못 대면 문제로 올리지 않는다.** 파일과 줄 번호가 없는 문제는 적지 않는다
- **추측하지 않는다.** 코드에서 보이지 않는 것은 「확인하지 못한 영역」에 적는다
- **비개발자가 읽을 말로 쓴다.** 용어가 아니라 무슨 일이 생기는지를 적는다
- **소스 코드를 보내지 않는다.** 결과 파일만 올린다

## 이 폴더

```
komit-scan/
├─ PLAN.md                  구현 계획
├─ .claude-plugin/          플러그인 설정
├─ skills/komit-scan/       검사 지시문
│  ├─ SKILL.md              절차
│  └─ references/           분류별 상세
├─ schema/                  결과 파일 형식
└─ fixtures/                검사 품질을 재는 정답표와 회차 결과
```

검사 대상은 저장소 루트의 `demo/soap-shop` 이다. **일부러 결함을 심어 둔 코드이므로** 배포하거나 복사하지 않는다. [`fixtures/README.md`](fixtures/README.md) 를 본다.
