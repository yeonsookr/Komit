# 비용 · 인계 · AI 잔재 · 기타

네 분류를 함께 본다. 전체를 얕게 훑으면 되는 것들이다.

**너무 많이 적지 않는다.** 이 네 분류는 건수가 쉽게 불어나는데, 목록이 길어지면 의뢰인이 정작 중요한 것을 놓친다. 분류마다 위에서부터 **다섯 건 정도**로 끊는다.

## 심각도 표

**여기 적힌 값을 그대로 쓴다.** 다시 판단하지 않는다.

| 분류 | 항목 | 심각도 |
| --- | --- | --- |
| 비용 | 외부 유료 서비스 호출에 상한이 없다 | 실제 사용자가 있으면 `HIGH`, 아직 없으면 `MEDIUM` |
| 비용 | 쉬지 않고 물어본다 | `MEDIUM` |
| 비용 | 쌓이는 자료를 한 번에 다 불러온다 | `MEDIUM` |
| 비용 | 목록을 돌면서 하나씩 물어본다 | `MEDIUM` |
| 비용 | 원본 그림을 그대로 내보낸다 | `LOW` |
| 인계 | 실행 방법이 적혀 있지 않다 | `MEDIUM` |
| 인계 | 어떤 환경변수가 필요한지 알 수 없다 | `MEDIUM` |
| 인계 | 특정 컴퓨터에서만 돈다 | `MEDIUM` |
| 인계 | 자료 구조를 알 수 없다 | `MEDIUM` |
| AI 잔재 | 없는 것을 불러 실행이 막힌다 | `HIGH` |
| AI 잔재 | 없는 것을 부르지만 쓰이지 않는 코드다 | `LOW` |
| AI 잔재 | 같은 기능이 두 곳에 다르게 들어 있다 | `MEDIUM` |
| AI 잔재 | **쓰이는 자리가 만들다 만 채로 성공만 돌려준다** | **`HIGH`** |
| AI 잔재 | 쓰이지 않는 자리가 만들다 만 채로 있다 | 적지 않는다 |
| AI 잔재 | 붙여넣기 한 곳만 고쳐져 있다 | `MEDIUM` |
| 기타 | 오류를 잡아 처리하는 곳이 없다 | `MEDIUM` |
| 기타 | 문제가 생겨도 알 수 없다 | `MEDIUM` |
| 기타 | 개발용과 운영용이 섞여 있다 | `MEDIUM`. 결제 관련이면 `결제` 분류로 옮기고 `HIGH` |
| 기타 | 좁은 화면에서 깨진다 | `LOW` |
| 기타 | 검색에 안 나온다 | `LOW` |

굵게 표시한 항목을 특히 주의한다. 취소 버튼을 눌렀는데 취소되지 않고 성공만 돌아오면, 의뢰인은 **문제가 있는 줄도 모른다.** 겉으로는 되는 것처럼 보이므로 `HIGH`다.

## 네 분류를 모두 확인한다

앞쪽 분류를 보다 보면 뒤쪽 분류를 건너뛰기 쉽다. **네 분류를 각각 따로 훑는다.**

한 건도 나오지 않은 분류가 있으면, 없는 것이 맞는지 다시 본다. 다시 봐도 없으면 그대로 둔다. **없는데 억지로 만들지 않는다.** 다만 「확인한 영역」에 그 분류를 무엇을 보고 없다고 판단했는지 한 줄 남긴다.

```
확인한 영역에 이렇게 적는다
  비용 — 외부 서비스 호출부와 목록 조회부를 보았고, 상한이 필요한 곳을 찾지 못했다
```

# 비용

바이브코딩에서 자주 나는 사고다. 요금이 갑자기 몇십 배로 뛴다.

읽을 곳 — 외부 서비스를 부르는 곳, 목록을 불러오는 곳, 반복해서 도는 코드.

## 이 분류의 판단 기준

**지금 당장이 아니라 사람이 늘었을 때를 본다.**

지금 자료가 네 건뿐이어도, 그 자료가 늘어나는 성질이면 문제다. 상품·주문·회원·게시글처럼 **쌓이는 자료**를 다루는 곳이면 지금 개수와 무관하게 본다.

| 지금 상태 | 판단 |
| --- | --- |
| 상품 네 개를 한 번에 다 가져온다 | **문제다.** 상품은 늘어난다 |
| 설정값 네 개를 한 번에 다 가져온다 | 문제가 아니다. 설정은 늘지 않는다 |
| 회원 목록을 한 번에 다 가져온다 | **문제다.** 회원은 늘어난다 |

"지금은 적으니까 괜찮다"로 넘기지 않는다. 의뢰인이 알고 싶은 것은 **출시한 뒤에 무슨 일이 생기는가**다.

---

## 1. 외부 서비스 호출에 상한이 없다

AI나 지도, 문자 같은 유료 서비스를 부르는데 횟수 제한이 없는 경우.

### 볼 것

- 한 사용자가 얼마나 자주 부를 수 있는가
- 실패했을 때 계속 다시 부르는가
- 사용자가 준 값만큼 반복해서 부르는가

### 이렇게 쓴다

```
제목   AI 기능을 무제한으로 쓸 수 있습니다
설명   한 사람이 계속 눌러도 막지 않아 요금이 크게 나올 수 있습니다
분류   비용
심각도 실제 사용자가 있으면 HIGH, 아직 없으면 MEDIUM
```

---

## 2. 쉬지 않고 물어본다

화면이 몇 초마다 서버에 계속 물어보는 경우. 사람이 많아지면 요청 수가 폭증한다.

심각도 `MEDIUM`.

---

## 3. 전부 다 불러온다

목록을 끊어서 가져오지 않고 한 번에 다 가져오는 경우. 자료가 쌓이면 점점 느려지다가 멈춘다.

**가장 자주 나오고 가장 자주 놓치는 항목이다.** 지금 자료가 적다고 넘기지 않는다. 위의 판단 기준을 본다.

### 찾는 법

쌓이는 자료를 다루는 곳에서 **개수를 제한하는 말이 없는지** 본다.

- 목록을 가져오는 곳에 몇 개까지 가져올지 정하는 값이 있는가
- 몇 번째부터 가져올지 정하는 값이 있는가
- 화면에 다음 쪽으로 넘어가는 장치가 있는가

셋 다 없으면 문제다. 상품 목록, 주문 내역, 회원 목록, 게시글 목록이 특히 그렇다.

```
제목   상품 목록을 한 번에 다 불러옵니다
설명   상품이 쌓이면 화면이 점점 느려지다가 열리지 않게 됩니다
심각도 MEDIUM
```

---

## 4. 목록을 돌면서 하나씩 물어본다

목록 하나마다 따로 조회하는 구조. 열 개면 열한 번, 백 개면 백한 번 부른다.

심각도 `MEDIUM`.

---

## 5. 원본 그림을 그대로 내보낸다

줄이지 않은 사진을 그대로 보내는 경우. 전송량 요금이 크게 나온다.

심각도 `LOW`.

---

# 인계

**Komit에만 있는 검사다.** 다른 도구는 "이 코드를 남에게 넘긴다"는 전제가 없다.

개발자가 받아서 일할 수 있는 상태인지 본다. 이게 안 되면 견적 자체가 안 나온다.

읽을 곳 — README, 패키지 정의, 환경변수 예시 파일, 설정 파일.

---

## 1. 실행 방법이 적혀 있지 않다

### 볼 것

- README가 있는가
- 무엇을 설치하고 어떻게 띄우는지 적혀 있는가
- 처음 만들었을 때의 기본 문구 그대로인가

### 이렇게 쓴다

```
제목   실행 방법 문서 추가
설명   받아 든 개발자가 어떻게 띄우는지 알 수 없습니다
분류   인계
심각도 MEDIUM
```

---

## 2. 어떤 환경변수가 필요한지 모른다

코드는 환경변수를 쓰는데 목록이 어디에도 없는 경우.

### 볼 것

- 코드에서 읽는 환경변수를 모아 본다
- 예시 파일이 있는가
- 그 목록이 코드에서 쓰는 것과 맞는가

### 이렇게 쓴다

```
제목   환경변수 목록 파일 추가
설명   무엇을 채워야 하는지 알 수 없어 받아도 띄울 수 없습니다
심각도 MEDIUM
```

**주의** — 예시 파일에는 이름만 적고 실제 값은 적지 않는다.

---

## 3. 특정 컴퓨터에서만 돈다

절대 경로나 개인 계정 정보가 코드에 박혀 있는 경우.

```
제목   다른 컴퓨터에서는 실행되지 않습니다
설명   특정 컴퓨터의 폴더 위치가 코드에 박혀 있습니다
심각도 MEDIUM
```

---

## 4. 자료 구조를 알 수 없다

데이터베이스를 쓰는데 표 구조가 코드 어디에도 없는 경우.

`데이터` 분류와 겹친다. **실행을 못 하는 문제면 `인계`, 구조를 못 만드는 문제면 `데이터`로 둔다.** 둘 다 적지 않는다.

---

# AI 잔재

**이것도 Komit에만 있는 검사다.** 다른 도구는 "AI가 썼다"고 가정하지 않는다.

읽을 곳 — 전체를 얕게. 비슷한 이름의 파일이 여럿인지, 안 쓰는 파일이 남아 있는지 본다.

---

## 1. 없는 것을 부른다

AI가 있지도 않은 함수나 라이브러리를 만들어 쓴 경우.

### 볼 것

- 가져오는 라이브러리가 패키지 목록에 있는가
- 부르는 함수가 실제로 정의되어 있는가

### 이렇게 쓴다

```
제목   설치되지 않은 기능을 부르고 있습니다
설명   이 화면을 열면 오류가 납니다
분류   AI 잔재
심각도 실행이 막히면 HIGH, 안 쓰는 코드면 LOW
```

---

## 2. 같은 기능이 두 곳에 다르게 들어 있다

AI가 다시 만들면서 예전 것을 지우지 않은 경우. 어느 쪽이 도는지 헷갈리고, 고칠 때 한쪽만 고치게 된다.

### 볼 것

- 이름이 비슷한 파일이 여럿 있는가 (`payment.ts` 와 `payment-old.ts` 같은)
- 같은 일을 하는 함수가 여러 곳에 있는가

```
제목   같은 결제 처리가 두 곳에 다르게 들어 있습니다
설명   고칠 때 한쪽만 고치면 문제가 계속 남습니다
심각도 MEDIUM
```

---

## 3. 만들다 만 자리가 남아 있다

`TODO`나 빈 함수가 그대로 남아 있고, 그 자리가 실제로 쓰이는 경우.

### 볼 것

- `TODO`, `FIXME` 가 달린 곳이 실제로 불리는가
- 아무것도 하지 않고 성공만 돌려주는 함수가 있는가

**쓰이지 않는 자리는 적지 않는다.** 실제로 불리는 것만 적는다.

```
제목   주문 취소가 아무 일도 하지 않습니다
설명   취소 버튼을 눌러도 실제로는 취소되지 않습니다
심각도 HIGH
```

---

## 4. 붙여넣기 한 곳만 고쳐져 있다

같은 코드가 여러 곳에 있는데 일부만 고쳐진 경우.

심각도 `MEDIUM`.

---

# 기타

위 어디에도 안 들어가는 것. **잡동사니 통이 되지 않게 한다.** 다른 분류에 넣을 수 있으면 그쪽에 넣는다.

---

## 1. 오류가 나면 아무것도 안 나온다

오류를 잡아서 처리하는 곳이 없어 화면이 멈추거나 빈 화면이 되는 경우.

```
제목   오류가 나면 빈 화면이 됩니다
설명   무엇이 잘못됐는지 알 수 없어 사용자가 그냥 나갑니다
심각도 MEDIUM
```

---

## 2. 문제가 생겨도 알 수 없다

기록을 남기거나 오류를 모으는 장치가 전혀 없는 경우.

개발자에게 맡길 때도 문제가 된다. 재현 기록이 없으면 원인을 못 찾는다.

심각도 `MEDIUM`.

---

## 3. 개발용과 운영용이 섞여 있다

테스트 값과 실제 값이 구분 없이 한 곳에 있는 경우.

심각도 `MEDIUM`. 결제 관련이면 `결제` 분류로 옮기고 `HIGH`.

---

## 4. 좁은 화면에서 깨진다

고정된 너비를 써서 휴대전화에서 화면이 밀려나는 경우.

```
제목   모바일에서 레이아웃이 깨집니다
설명   좁은 화면에서 상품 목록이 화면 밖으로 밀려납니다
심각도 LOW
```

---

## 5. 검색에 안 나온다

제목이나 설명 같은 기본 정보가 비어 있는 경우.

심각도 `LOW`.

---

## 코드로 확인할 수 없는 것

| 무엇 | 왜 |
| --- | --- |
| 실제 요금이 얼마나 나오는지 | 사용량을 봐야 안다 |
| 실제 화면이 얼마나 느린지 | 돌려 보아야 안다 |
| 배포 환경에 기록 장치가 붙어 있는지 | 운영 환경에 있다 |
| 안 쓰는 코드가 정말 안 쓰이는지 | 확신이 없으면 적지 않는다 |
