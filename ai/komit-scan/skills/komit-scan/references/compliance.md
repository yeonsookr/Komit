# 위법 검사

한국에서 서비스를 열 때 갖춰야 하는 것을 본다. 다른 검사 도구가 보지 않는 영역이고, 의뢰인이 가장 모르는 영역이다.

코드 로직보다 **있는지 없는지**를 본다. 가장 가볍다.

---

## 먼저 — 여기서 특히 조심할 것

### 1. 조문 번호와 과태료 금액을 쓰지 않는다

법은 바뀌고, 금액은 사안마다 다르다. **틀린 법 정보를 주면 없느니만 못하다.**

```
나쁨  개인정보 보호법 제30조 위반으로 과태료 1천만원 이하
좋음  개인정보처리방침이 없습니다. 실제 사용자를 받는 순간부터 필요합니다
```

무엇이 없는지와 언제부터 필요한지만 쓴다.

### 2. 적용 여부를 단정하지 않는다

대부분의 위법 항목은 **운영 상태에 따라 적용이 갈린다.** 코드만 봐서는 모른다.

| 코드로 아는 것 | 코드로 모르는 것 |
| --- | --- |
| 결제 처리 코드가 있다 | 실제로 결제를 받고 있나 |
| 회원가입 화면이 있다 | 실제 사용자가 들어오고 있나 |
| 상품 목록이 있다 | 사업자등록을 했나 |

모르는 쪽은 **문제로 단정하지 말고 물어볼 것으로 만든다.**

### 3. 확실한 것만 적는다

없는 것이 눈에 보이는 항목만 적는다. 애매하면 「확인하지 못한 영역」으로 넘긴다.

---

## 심각도 표

**여기 적힌 값을 그대로 쓴다.** 다시 판단하지 않는다.

| 항목 | 심각도 |
| --- | --- |
| 개인정보처리방침이 없다 — 회원 기능이나 주문이 있을 때 | `HIGH` |
| 개인정보처리방침이 없다 — 아직 아무것도 받지 않을 때 | `MEDIUM` |
| 회원 탈퇴 경로가 없다 — 가입이 있을 때 | `HIGH` |
| 주민등록번호를 받는다 | `HIGH` |
| 이용약관이 없다 | `MEDIUM` |
| 판매자 정보를 밝히지 않는다 | `MEDIUM` |
| 환불·교환·배송 안내가 없다 | `MEDIUM` |
| 개인정보 수집 동의 절차가 없다 | `MEDIUM` |
| 꼭 필요한 항목과 선택 항목을 나누지 않았다 | `MEDIUM` |

위법 항목은 **없으면 곧바로 과태료 대상**이 되는 것과, 갖추면 좋은 것이 나뉜다. 위 표가 그 구분이다. 임의로 올리거나 내리지 않는다.

---

## 1. 개인정보처리방침

**개인정보를 받으면 필요하다.** 위법 항목 중 가장 자주 빠지고 가장 확실하다.

### 볼 것

- 개인정보처리방침 페이지가 있는가
- 있다면 화면 어딘가에서 갈 수 있는가. 주소만 있고 연결이 없으면 없는 것과 같다
- 회원가입이나 주문 화면에서 볼 수 있는가

### 어떻게 찾나

`privacy`, `개인정보` 가 든 경로·파일·화면 문구. 바닥글 링크 목록.

### 이렇게 쓴다

```
제목   개인정보처리방침 페이지 추가
설명   실제 사용자를 받는 순간부터 필요합니다
분류   위법
심각도 회원 기능이나 주문이 있으면 HIGH, 아직 아무것도 안 받으면 MEDIUM
```

---

## 2. 이용약관

법이 직접 요구하는 것은 아니지만, 없으면 분쟁이 났을 때 기준이 없다. 개인정보처리방침과 함께 둔다.

`terms`, `약관` 이 든 경로를 본다.

심각도는 `MEDIUM`.

---

## 3. 회원 탈퇴 경로

**가입이 되면 탈퇴도 되어야 한다.** 가입만 있고 탈퇴가 없는 경우가 아주 흔하다.

### 볼 것

- 회원가입이나 로그인이 있는가
- 탈퇴 화면이나 탈퇴 처리가 있는가
- 탈퇴하면 자료를 어떻게 하는지 정해져 있는가

### 이렇게 쓴다

```
제목   회원탈퇴 경로 구현
설명   가입은 되는데 탈퇴할 방법이 없습니다
심각도 HIGH
```

탈퇴 시 자료를 지울지 남길지는 코드로 알 수 없다. **물어볼 것으로 만든다.**

```
문항   기존 회원 데이터를 유지해야 하나요?
보기   유지해야 합니다 / 지워도 괜찮습니다
근거   회원 기능은 있는데 탈퇴 경로가 없다. 자료를 남겨야 하는지에 따라
       탈퇴를 어떻게 만들지가 달라진다.
```

---

## 4. 판매자 정보 표시

물건이나 서비스를 파는 화면이 있으면 파는 사람이 누구인지 밝혀야 한다.

### 밝혀야 하는 것

상호 · 대표자 이름 · 주소 · 전화번호 · 전자우편 주소 · 사업자등록번호 · 통신판매업 신고번호

보통 바닥글에 모아 둔다.

### 볼 것

- 결제나 주문 기능이 있는가
- 바닥글이나 안내 화면에 위 항목이 있는가

### 이렇게 쓴다

```
제목   판매자 정보 표시 추가
설명   상호·대표자·사업자등록번호·연락처를 화면에 밝혀야 합니다
심각도 MEDIUM
```

사업자등록을 했는지, 통신판매업 신고를 했는지는 코드로 알 수 없다. 자리만 비어 있으면 그것을 적고, 등록 여부 자체는 단정하지 않는다.

---

## 5. 환불·교환·배송 안내

파는 화면이 있으면 사는 사람이 **사기 전에** 이 조건을 볼 수 있어야 한다.

### 볼 것

- 환불이나 교환 안내 화면이 있는가
- 배송 방법과 기간 안내가 있는가
- 주문하기 전에 볼 수 있는 자리에 있는가

### 이렇게 쓴다

```
제목   환불·교환 안내 페이지 추가
설명   사기 전에 환불 조건을 볼 수 있어야 합니다
심각도 MEDIUM
```

---

## 6. 개인정보 수집 동의

회원가입이나 주문 화면에서 개인정보를 받을 때, 무엇을 왜 받는지 알리고 동의를 받아야 한다.

### 볼 것

- 가입·주문 화면에 동의 절차가 있는가
- **꼭 필요한 항목과 선택 항목이 나뉘어 있는가.** 선택 항목까지 동의해야만 가입되게 만들면 안 된다
- 광고·마케팅 수신 동의를 따로 받는가

### 이렇게 쓴다

```
제목   가입할 때 선택 항목까지 반드시 동의하게 되어 있습니다
설명   꼭 필요한 항목과 선택 항목을 나눠 받아야 합니다
심각도 MEDIUM
```

---

## 7. 주민등록번호

**함부로 받을 수 없는 항목이다.** 법에 근거가 있는 경우가 아니면 받으면 안 된다.

### 볼 것

- 주민등록번호를 받는 입력칸이나 저장 자리가 있는가

있으면 `HIGH`로 적는다. 대부분의 작은 서비스는 받을 근거가 없다.

```
제목   주민등록번호를 받지 않도록 바꾸기
설명   법에 정해진 경우가 아니면 받을 수 없는 항목입니다
심각도 HIGH
```

암호화 여부는 `보안`의 개인정보 암호화에서 따로 본다.

---

## 8. 만 14세 미만

나이를 받거나 어린 사용자가 쓸 만한 서비스라면, 만 14세 미만은 보호자 동의가 필요하다.

해당할 것 같으면 문제로 단정하지 말고 **물어볼 것으로 만든다.**

```
문항   만 14세 미만도 쓸 수 있는 서비스인가요?
보기   네 / 아니요
근거   나이를 받는 입력칸을 찾았다. 만 14세 미만이 쓴다면
       보호자 동의 절차가 따로 필요하다.
```

---

## 물어볼 것 — 이 분류에서 많이 나온다

위법은 코드로 판정할 수 없는 항목이 많아, 물어볼 것의 대부분이 여기서 나온다. 다만 **다섯 개 제한은 전체 기준이다.** 위법에서만 다섯 개를 채우지 않는다.

우선순위:

| 순위 | 문항 | 언제 만드나 |
| --- | --- | --- |
| 1 | 실제 사용자가 들어오고 있나요 | 개인정보를 받는 화면을 찾았을 때 |
| 2 | 실제 결제를 받을 계획인가요 | 결제 처리 코드를 찾았을 때 |
| 3 | 기존 회원 데이터를 유지해야 하나요 | 회원 기능은 있고 탈퇴가 없을 때 |
| 4 | 사업자등록을 하셨나요 | 판매 화면은 있고 판매자 정보가 없을 때 |

---

## 코드로 확인할 수 없는 것

「확인하지 못한 영역」에 넣는다.

| 무엇 | 왜 |
| --- | --- |
| 사업자등록·통신판매업 신고 여부 | 코드 밖의 일이다 |
| 실제로 개인정보를 받고 있는지 | 돌아가는 서비스를 봐야 안다 |
| 약관 내용이 적절한지 | 문서의 내용 판단은 이 검사의 범위가 아니다 |
| 개인정보를 어디에 얼마나 보관하는지 | 운영 환경에 있다 |
