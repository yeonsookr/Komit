# 검사 품질을 재는 자료

`komit-scan` 이 찾아야 할 것을 찾는지, 없는 것을 만들어내지 않는지 재기 위한 자료다.

**이 폴더는 개발용이다.** 데모에서 보여주는 것은 저장소 루트의 [`demo/`](../../../demo) 쪽이다.

---

## 구조

시험 대상 하나가 폴더 하나다.

```
fixtures/
└─ <대상 이름>/
   ├─ EXPECTED.md    정답표. 심어 둔 결함과 일부러 정상으로 둔 코드
   ├─ RUNS.md        회차 기록. 무엇을 고쳤고 무엇이 나아졌나
   └─ runs/          회차별 결과 파일. 001, 002, … 순서로 쌓는다
```

대상의 코드 자체는 `demo/` 에 있다. 여기에는 **재는 자료만** 둔다.

| 대상 | 코드 | 스택 | 심은 결함 | 마지막 회차 |
| --- | --- | --- | --- | --- |
| [`soap-shop`](soap-shop/) | [`demo/soap-shop`](../../../demo/soap-shop) | Next.js · 파일 저장 | 31건 | [003](soap-shop/RUNS.md) |

## 왜 필요한가

검사기는 AI 가 지시문을 따라 도는 것이라 **돌릴 때마다 결과가 조금씩 다르다.** 지시문을 고쳤을 때 나아졌는지 나빠졌는지 알 방법이 없으면 고치는 일이 도박이 된다.

정답표가 있으면 잴 수 있다. 실제로 이렇게 썼다.

| 관측 | 고친 것 | 다음 회차 |
| --- | --- | --- |
| 비용 분류가 0건이었다 | `hygiene.md` 에 판단 기준 추가 | 3건 |
| 같은 문제에 심각도가 회차마다 달랐다 | 참고 파일에 심각도 표 추가 | 고정됨 |

---

## 무엇을 재는가

| 재는 것 | 어떻게 |
| --- | --- |
| 찾아야 할 것을 찾았나 | `EXPECTED.md` 의 「심어 둔 결함」과 맞춰 본다 |
| **없는 것을 만들어내지 않았나** | 「일부러 정상으로 둔 것」을 문제라고 적었는지 본다 |
| 분류·심각도가 맞나 | 정답표의 값과 비교한다 |
| 점수가 규칙대로인가 | `docs/RULES.md` 의 계산과 맞춰 본다 |
| 회차마다 같은가 | `runs/` 의 지난 결과와 비교한다 |
| 빈 분류가 없나 | 여덟 분류 중 0건인 곳을 본다 |

**두 번째가 가장 중요하다.** 없는 문제를 만들어내면 의뢰인이 필요 없는 일을 개발자에게 맡기게 된다.

그래서 비슷하게 생긴 코드를 짝으로 두고 한쪽만 결함으로 만들어 둔다. 예를 들어 `soap-shop` 의 내 주문 목록은 소유권을 확인하고, 주문 상세는 확인하지 않는다.

---

## 돌려 보기

스킬을 먼저 복사한다. 복사본은 커밋되지 않는다.

```bash
cp -r ai/komit-scan/skills/komit-scan .claude/skills/
```

그다음 **새 세션에서** 이렇게 요청한다.

```
demo/soap-shop 을 komit-scan 으로 검사해줘
```

지시문을 쓴 세션에서 돌리면 시험이 되지 않는다. 빠뜨린 부분을 기억으로 메꾸기 때문이다.

**검사를 돌리는 쪽은 `EXPECTED.md` 를 읽지 않는다.** 정답을 보고 답을 쓰면 아무것도 재지 못한다.

끝나면 결과 파일을 `runs/` 에 다음 번호로 넣고 `RUNS.md` 에 한 줄 적는다.

---

## 시험 대상을 새로 만들 때

지금은 `soap-shop` 하나뿐이다. 다른 스택이나 다른 결함을 재려면 대상을 늘린다.

### 무엇을 늘려야 하나

| 아직 못 재는 것 | 필요한 대상 |
| --- | --- |
| 외부 데이터베이스의 권한 설정 | Supabase 같은 것을 쓰는 대상 |
| 파이썬·자바 프로젝트 | 그 스택으로 만든 대상 |
| 큰 코드베이스에서의 정확도와 비용 | 파일 수가 많은 대상 |
| 결함이 드문 프로젝트 | 거의 멀쩡한 대상. 헛것을 재기에 좋다 |

### 만드는 법

1. `demo/<이름>/` 에 실제로 도는 앱을 만든다. **돌아가는 코드와 뚫린 코드가 섞여 있어야** 헛것을 잴 수 있다
2. 비슷하게 생긴 코드를 짝으로 두고 한쪽만 결함으로 만든다
3. `fixtures/<이름>/EXPECTED.md` 에 심은 결함과 **일부러 정상으로 둔 것**을 함께 적는다
4. `fixtures/<이름>/RUNS.md` 를 만들고 첫 회차부터 기록한다
5. 위 「지금 있는 대상」 표에 한 줄 더한다
6. `demo/README.md` 의 대상 목록에도 더한다

### 주의

대상의 코드에는 결함이 의도적으로 들어 있다. 배포하지 않고, 다른 프로젝트에 복사하지 않고, 로컬에서만 띄운다.
